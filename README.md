# Связка — камеры команды для OBS

Рабочая первая версия: сайт на Vercel, собственный сервер сигналинга и прямой WebRTC между устройствами. Не использует LiveKit или VDO.Ninja.

## Что работает

- Комната до 6 участников, приглашение по секретной ссылке.
- Каждый участник может передавать камеру и по желанию микрофон.
- Выбор камеры, профили 720p/30, 1080p/30 и 1080p/60; реальный результат зависит от устройства и сети.
- Отдельная ссылка каждой камеры для источника «Браузер» в OBS.
- Предпросмотр выбранных камер в комнате без звука, чтобы не создавать обратную связь.
- Автоматическое восстановление соединения; после перезагрузки страницы камеру нужно включить снова.
- Остановка камеры, отзыв старой ссылки OBS, статистика FPS и потерь.
- Мобильная компоновка и запрос удержания экрана включённым, когда браузер это поддерживает.

## Запустить на компьютере

Требуется Node.js 22+ и pnpm 11.

```sh
pnpm install
pnpm dev
```

Откройте `http://localhost:8787`. Создайте комнату, откройте приглашение в другом браузере или профиле. Доступ к камере на localhost разрешён браузерами. Для телефона и удалённых пользователей нужен публичный адрес HTTPS; адрес localhost на телефоне указывает на сам телефон, а не на компьютер.

Локальный запуск использует STUN, но не включает TURN автоматически. В одной сети прямое соединение часто работает; в разных сетях без TURN может не установиться.

## Опубликовать

Нужны две части. Платные ресурсы автоматически не создаются.

### 1. Сайт на Vercel

Загрузите этот каталог в свой Git-репозиторий и импортируйте его в Vercel. Настройки уже заданы в `vercel.json`:

- Framework: Other.
- Build command: `node scripts/build.mjs`.
- Output directory: `dist`.
- Environment variable: `PUBLIC_SIGNAL_URL=wss://адрес-вашего-сервера-подключения`.

Создайте production deployment. Собственный домен не обязателен: подойдёт адрес проекта `.vercel.app`. После изменения переменной нужно повторить deployment. Без `PUBLIC_SIGNAL_URL` интерфейс откроется, но честно сообщит, что подключение не настроено.

### 2. Сервер подключения

Разместите этот же проект на сервере с постоянно работающим Node.js и поддержкой WebSocket. Команда установки: `pnpm install --frozen-lockfile --prod`, запуска: `node server/index.mjs`. Также подготовлен Dockerfile.

Серверу задайте переменные окружения:

```dotenv
PORT=8787
ALLOWED_ORIGINS=https://ваш-проект.vercel.app
STUN_URL=stun:stun.l.google.com:19302
TURN_URLS=turn:ваш-turn-сервер:3478?transport=udp,turns:ваш-turn-сервер:5349?transport=tcp
TURN_SECRET=секрет-который-настроен-в-coturn
```

Несколько разрешённых адресов сайта можно указать через запятую. Укажите точный origin без завершающего `/`; wildcard намеренно не используется. Для нового домена или Vercel preview добавьте соответствующий origin.

Платформа хостинга или обратный прокси должны обеспечивать HTTPS/WSS и проксировать WebSocket endpoint `/ws`. `GET /health` проверяет работоспособность; он не раскрывает секреты.

Файл `.env.example` — образец, он не загружается автоматически. На хостинге задавайте переменные в его панели. Локально можно скопировать его в `.env` и запустить `node --env-file=.env server/index.mjs`, подставив локальные ALLOWED_ORIGINS.

### 3. Резервное соединение TURN

Для реальных мобильных сетей подключите coturn или совместимый TURN-сервис с временными HMAC-учётными данными. В coturn включите `use-auth-secret`, задайте `static-auth-secret`, совпадающий с `TURN_SECRET`, `realm`, публичный IP, диапазон relay-портов и ограничения трафика. Для `turns:` нужны TLS-сертификат и открытый TLS-порт. Откройте соответствующие UDP/TCP и relay-порты в firewall.

Секрет coturn хранится только на сервере подключения. Браузер получает временные реквизиты на 24 часа; приложение обновляет их каждые 30 минут. TURN пересылает зашифрованный WebRTC-трафик и расходует пропускную способность сервера.

## Использовать в OBS

1. На телефоне войдите в комнату и нажмите «Включить камеру».
2. На компьютере войдите в ту же комнату и нажмите «Ссылка OBS» у нужного участника.
3. OBS → Источники → Добавить → Браузер. Вставьте **полную ссылку вместе с частью после `#`**.
4. Задайте 1920 × 1080 и расположите источник поверх захвата игры. Для портретной композиции можно выбрать 1080 × 1920; видео сохраняет пропорции.
5. Если нужен звук, включите микрофон на телефоне до начала передачи. Для отдельного управления звуком источника используйте соответствующую настройку источника «Браузер» в своей версии OBS.

В OBS передаётся чистое видео без интерфейса комнаты. При отключённой камере отображается статус ожидания; после возвращения камеры источник подключается автоматически. Кнопка «Отозвать ссылку OBS» отключает старую ссылку, но участники комнаты по-прежнему имеют доступ к новой.

## Границы первой версии

- Комнаты хранятся в памяти одного процесса. После перезапуска сервера нужно создать новую комнату; пустая комната удаляется примерно через 5 минут. Не запускайте несколько экземпляров сервера без общего хранилища и маршрутизации.
- Ссылки являются ключами доступа. В OBS-ссылке есть доступ только к одной камере; приглашение даёт права участника всей комнаты. Нет аккаунтов, ролей модератора и постоянной истории.
- P2P создаёт отдельный исходящий видеопоток для каждого получателя. 3 зрителя потока по 6 Мбит/с потребуют примерно 18 Мбит/с исходящего канала телефона плюс накладные расходы. Для массовой раздачи нужен SFU.
- Лимит — 6 участников и до 24 отдельных OBS-подключений на комнату. Это программные ограничения, а не гарантия производительности телефона.
- Передача сжата видеокодеком. Не обещает отсутствие потерь, неизменный битрейт, 1080p/60 на любом телефоне или работу камеры при блокировке экрана. Локальной записи оригинала в этой версии нет.
- Перед публичным сервисом на много пользователей потребуются учётные записи/лимиты создания комнат и защита от злоупотребления серверным трафиком. Эта версия предназначена для небольшой доверенной команды.

## Проверки

```sh
pnpm test
pnpm build
```

Серверные тесты проверяют изоляцию комнат, доступ OBS только к одной камере, запрет публикации зрителем, отзыв ссылки, лимит 6 участников и восстановление сессии.

Дополнительно проведён локальный браузерный тест в Chrome с искусственными камерами: одновременная передача в обе стороны и в отдельное окно OBS-источника, мобильная ширина 390px, остановка/повторное включение, перезагрузка отправителя и отзыв ссылки. Протестирован optional read-only WebMCP-инструмент состояния через браузерный тестовый интерфейс. Реальные iPhone/Android, разные мобильные сети, TURN и приложение OBS пока не проверены.

## Файлы

- `public/` — интерфейс и клиент WebRTC.
- `server/index.mjs` — сигналинг, комнаты, разрешения и временные TURN-реквизиты.
- `scripts/build.mjs` — статическая сборка для Vercel.
- `tests/server.test.mjs` — тесты границ доступа.
- `vercel.json`, `Dockerfile`, `.env.example` — подготовка публикации.
